Update: the dashboard in this PR was built into firmware images and tested on both boards.

Images: tezuka_fw v0.3.23 plus the open fixes, maia-sdr PR 12 and this branch (test branch `test/allfixes-pr12-layout-main` on my fork). Pluto+ from the SD image, Pluto from the `.frm`. The dashboard file inside each image is byte-identical to the page I tested in the browser.

Since the first version of this PR: unit-circle normalised real/imaginary plots (default: peak at 1 + j0, fixed scale), a bin-number scale along the top of the I/Q plots, peak markers (first and second peak, with frequency and level) on all four views, a 2nd-peak readout line, and an `OVER REF` marker on the Spectrum page when bins are above the REF level and drawn flat at the top edge.

Results with the images (the other board transmits over the 40 dB cable): both boards boot, maia-httpd and the four maia-sdr devices are up, no kernel oops, BIST ok. Suite at 2.5, 10, 20, 30.72 and 61.44 MS/s on both boards: 70 results ok, none failed. I/Q frame rotation measured minus predicted -0.0009 to +0.0022 rad, scatter at most 0.0022 rad, OFDM log correlation 0.988 to 0.999. Unequal two-tone test (second tone 12 dB lower) from the flashed Pluto's own web server: peak marker at 2400.869141 MHz, 66.4 dB, second marker at 2400.891113 MHz, 53.6 dB, the same as the python decode (66.4 and 53.7 dB).

Not tested with the images: the other views from the flashed boards (tested from RAM with the same file), other boards, touch. Details, tables and screenshots: `Dashboard/docs/complex-iq/README.md`.
